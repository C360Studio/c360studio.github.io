// Why Sem* Feels Different

Graph speed inside.
Standards at the edge.

Most teams want shared structure across streams, code, and agents, but nobody wants to force every service engineer to hand-author RDF blank-node chains just to save application state.

SemEngine splits that problem cleanly. Inside the box, programs work with fast six-part dot-separated IDs (org.platform.system.domain.type.instance) and flat predicates over NATS JetStream. No external triple store, no heavy runtime dependencies.

When an integration, analyst tool, or compliance gate calls for formal ontologies or W3C queries, SemVocab and SemSparql attach at the read-only edge—translating live state into BFO, CCO, SOSA, Turtle, or JSON-LD without touching how core services write data.

Local-first resilience

Built for real operational links as well as cloud clusters. State holds locally on the box and syncs cleanly when peer links return.

Rules first, models where needed

Deterministic rules handle fast, repeatable decisions at zero token cost. Models and agents step in when a decision genuinely benefits from judgment.

Graceful tiering

If an upstream model endpoint is unreachable or out of budget, ingestion, graph state, and deterministic rules keep running uninterrupted.

// How The Loop Runs

Observations, rules, and agents
on one substrate.

In a typical stack, telemetry lives in a message bus, repo context lives in bespoke RAG indexes, workflow state lives in Postgres, and agent transcripts disappear into log files.

In sem*, the live graph is the orientation layer across all of them. A sensor reading from SemConnect, an AST diff from SemSource, and a research run in SemTeams are all typed entities with explicit provenance—so rules and agents react to live structure instead of stitching context together by hand.

01 · Observe

Streams, source files, HTTP polls, and tool outputs land as typed entities with provenance rather than scrolling past in a flat log.

02 · Orient

Relationships update in real time—connecting what changed to the components, specs, or platforms it actually affects.

03 · Decide

Reactive rules evaluate graph changes continuously and trigger bounded model or decision calls only when needed.

04 · Act & Record

Components pass compact storage references instead of blowing up context windows, and record execution evidence right beside the run.

// Architecture Defaults

Hard invariants, handled up front.

A good substrate makes your application code smaller by settling concurrency, identity, and recovery rules once—so product repositories spend their lines on domain work instead of plumbing.

[01] Write Authority

Single writer, typed ports

One owner governs graph state transitions while producers and consumers talk through explicit contracts. SHACL shapes in SemVocab can even compile directly into write contracts.

[02] Deterministic Identity

Offline-safe IDs

Six-part entity IDs carry the deployment authority that minted them. Disconnected nodes never collide, and independent graphs can federate later without central coordination.

[03] Explicit Durability

Predictable restarts

Current entity facts rehydrate from state buckets; unacknowledged work redelivers over streams. Recovery behavior comes straight from the primitive you choose.

[04] Bounded Execution

References over payloads

Rules trigger components with iteration caps, explicit budgets, and storage references—keeping multi-step agent loops inspectable and context windows lean.

// Verification & Governance

Built so humans stay in command.

Responsibility can be delegated to software and agents; accountability cannot. Across the ecosystem, we pair deterministic Go harnesses with external conformance suites and explicit governance checks you can run yourself.

137 / 137

External OGC Conformance

SemConnect passes all 137 checks in the official OGC API Connected Systems test suite—an external standard we neither wrote nor grade.

NEAR

HAAG Governance

Necessity, Evidence, Authority, Recovery. Keep harness-recorded facts separate from model prose, bind approvals to exact revisions, and never invent zeros on uncertain failures.

0 Dial-Outs

Deterministic Harnesses

servicesim verifies exact vendor API & MCP requests offline while ateam keeps instructions, worktrees, mutation checks, and reviews unified across coding agents.
