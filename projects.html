// The Portfolio

Production & Labs.

We keep a clean line between Production (the core substrate, add-ons, products, tooling, and governance we actively build and run) and Labs, where specific questions about throughput, bounded decision models, or coordination mechanics get tested against real workloads first.

// Design Pressure

Real workloads shape the core.

Every repository in the sem* family exists to solve a concrete problem without bloating SemEngine. When an idea works best as an optional boundary, such as ontology packs, neural embeddings, or SPARQL, it lives in its own module so everyday applications stay fast and dependency-light.

Meanwhile, consumer products and labs push individual axes hard so architectural seams surface early:

  • Zero ontology taxSemVocab & SemSparql add formal IRIs, SHACL, and SPARQL 1.1 without complicating core writes.
  • Agentic loopsSemTeams coordinates multi-agent packs, sandboxes, and human gates on shared primitives.
  • Ingest & provenanceSemSource turns ASTs, git commits, docs, and configs into live graph entities.
  • StandardsSemConnect answers to 137 external OGC Connected Systems conformance checks.
  • Daily Go rigorateam and servicesim keep multi-agent Go repos and API tests reproducible.
  • Decision evalsSemSelect measures when specialized decision models actually beat code or chat models.
// Why SemEngine Is Modular

Putting full semantic-web machinery inside an operational database forces every engineer to write multi-step RDF graphs just to store basic state.

SemEngine keeps the core operational graph fast over NATS JetStream using flat dotted predicates and six-part entity IDs. When a partner integration or compliance audit needs BFO, CCO, SOSA, SHACL validation, or SPARQL 1.1, semvocab and semsparql plug in cleanly at the edge.

// SemStreams & SemDev Consolidation

SemEngine is replacing SemStreams, which will be retired once flagship consumers complete their cutover.

Likewise, SemDev's clean-room issue-to-PR workflow is being absorbed into SemTeams as a separately qualified development pack, keeping one unified agentic layer instead of parallel runtimes.

Production Core, add-ons, products, tooling & governance
