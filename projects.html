// The Ecosystem

One framework.
Many hard problems.

Semstreams is the substrate. Eleven projects are built on it, and each one pushes a different capability until the framework tells us where it breaks. Three more stand alongside it: standalone services the ecosystem depends on but doesn't build on.

// Why So Many

The products are the pressure.

Semstreams has no synthetic benchmark suite standing in for real use. Every sem* project below is something we actually needed, built by driving one capability past comfortable.

That means framework gaps arrive as product pain rather than as a passing test. A scheduler problem found in SemBoids at 30Hz is a scheduler fix upstream. A projection-contract problem found by SemConnect against the OGC conformance suite is a contract fix upstream. The consumers are the design pressure, and the framework is what survives them.

  • ThroughputSemBoids runs flocking physics with live graph snapshots at a tunable cadence.
  • RulesSemBoids again, steering flocks with JSON rules you toggle at runtime.
  • AgenticSemTeams, SemDev and SemMachina lean on loops, dispatch, tools and budgets.
  • Edge & offlineSemLink holds vehicle-local state and syncs to peers when it can.
  • StandardsSemConnect answers to a conformance suite we don't control.
  • Ingest scaleSemSource takes in code, docs, configs and media with provenance intact.
// What The Framework Carries

Every processor in SemTeams comes from Semstreams. graph, rule, agentic-dispatch, agentic-loop, agentic-model, agentic-tools, all of it wired up in one call at startup. A complete multi-agent product, and nobody had to write the processing path.

That freed the Go in SemTeams to be product. Roughly 23,000 lines of CLI, sandbox runtime and HTTP middleware, none of it spent reimplementing graphs, rules or agent loops.

Extending it stayed declarative too. SemTeams adds 34 vocabulary predicates of its own, with no fork, no patched processor and nothing waiting on an upstream PR.

Want to check? Search the repo for a component factory registration. There is exactly one, and it belongs to the framework.

// How To Read Status

Stage is where a project sits in its own life. Tracks is the Semstreams release it pins, which is the honest measure of how close it runs to the current framework.

An older pin means the project is resting, not rotting. The labs get picked back up in rotation, and the pin is where they resume.
